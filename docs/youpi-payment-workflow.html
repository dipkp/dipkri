YouPI PG · payment lifecycle

Where a rupee travels — and where it currently stops

The flow as the code actually runs today: store checkout creates the session, the gateway waits for bank evidence, reconciliation proves settlement, and only a signed webhook moves coins. The coral block is the uncommitted hook that short-circuits the middle.

Price

Comes from the page, not the admin

  • store.html renders #displayPrice (default ₹1.00) and posts it back.
  • Server clamps 1…MAX and derives coins = round(price).
  • No admin field feeds this — so an admin “price change” has no path to the site.

Receiver

One active VPA at a time

  • Activating a VPA deactivates the others by design.
  • Checkout picks findActiveForMerchant().
  • VPA table has no earnings column — per-receiver totals don’t exist.

Entries

Only RECONCILED moves coins

  • Webhook needs signature, amount match and delivery id.
  • Credits are idempotent via fulfillment_claims.
  • Balance = 50 + SUM(claims); base 50 is hardcoded.
